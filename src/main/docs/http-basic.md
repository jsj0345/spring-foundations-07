# HTTP 기본 구조 복습

> 요청과 응답, 무상태, 비연결성, 메시지 형식을 하나의 흐름으로 정리했다.

## 1. HTTP가 맡는 역할

HTTP는 클라이언트와 서버가 메시지를 주고받기 위한 규칙이다.

웹 문서뿐 아니라 다음과 같은 데이터도 HTTP 메시지로 전달할 수 있다.

- HTML과 일반 텍스트
- JSON, XML 같은 구조화 데이터
- 이미지와 영상
- 파일
- 서버 사이의 API 요청

프로토콜 버전마다 전송 최적화 방식에는 차이가 있지만 요청과 응답이라는 기본 모델은 동일하다.

## 2. 클라이언트와 서버의 역할 분리

```text
클라이언트 → 요청
서버       → 요청 처리
서버       → 응답
클라이언트 → 응답 사용
```

클라이언트는 화면과 사용자 상호작용에 집중하고 서버는 데이터와 업무 규칙을 담당할 수 있다.

역할이 분리되면 서버 구현을 바꾸더라도 약속된 HTTP 인터페이스가 유지되는 한 클라이언트와 독립적으로 발전시키기 쉽다.

## 3. 무상태

무상태는 서버가 이전 요청의 문맥을 자동으로 기억하지 않는다는 의미다.

```text
상태 의존 요청:
"두 개 주세요."
→ 서버가 앞 대화를 기억해야 이해 가능

무상태 요청:
"상품 A를 두 개 주문합니다."
→ 이 요청만으로 처리 가능
```

각 요청에 필요한 정보를 포함하면 어느 서버 인스턴스가 받아도 처리하기 쉬워진다. 그래서 서버를 여러 대로 확장하는 데 유리하다.

다만 로그인처럼 상태가 필요한 기능도 존재한다. 이때 쿠키, 세션, 토큰 같은 별도 수단으로 필요한 상태를 연결한다.

무상태는 상태가 절대 존재하지 않는다는 뜻이 아니라, HTTP 요청 자체가 앞 요청에 숨겨진 문맥을 과도하게 의존하지 않도록 설계한다는 뜻에 가깝다.

## 4. 비연결성과 지속 연결

요청이 끝난 뒤 연결을 계속 점유하지 않으면 많은 사용자가 접속하는 환경에서 서버 자원을 아낄 수 있다.

하지만 매 요청마다 TCP 연결을 처음부터 만들면 연결 수립 비용이 반복된다. HTML 하나를 받은 뒤 CSS, JavaScript, 이미지까지 각각 새 연결로 처리하면 지연도 커진다.

그래서 실제 통신에서는 하나의 연결을 여러 요청과 응답에 재사용하는 지속 연결이 사용된다.

```text
연결 생성
→ HTML 요청·응답
→ CSS 요청·응답
→ 이미지 요청·응답
→ 연결 종료
```

비연결성의 자원 효율과 연결 재사용의 성능 이점을 함께 이용하는 구조로 이해했다.

## 5. 요청 메시지

```http
GET /search?q=spring HTTP/1.1
Host: example.com

```

요청 시작 줄은 세 요소로 볼 수 있다.

```text
HTTP 메서드 + 요청 대상 + HTTP 버전
```

- 메서드: 서버에 기대하는 동작
- 요청 대상: 경로와 쿼리
- 버전: 사용할 HTTP 규칙

요청도 필요하면 본문을 가질 수 있다.

## 6. 응답 메시지

```http
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 18

{"result":"success"}
```

응답 시작 줄은 버전, 상태 코드, 상태 설명으로 구성된다.

상태 코드는 요청 처리 결과를 기계가 이해할 수 있도록 전달한다.

## 7. 공통 메시지 구조

```text
시작 줄
헤더
빈 줄
메시지 본문
```

헤더에는 본문 형식, 크기, 인증, 캐시, 압축 같은 부가 정보가 들어간다. 본문에는 실제 전달할 표현 데이터가 놓인다.

빈 줄은 헤더와 본문을 나누는 경계이므로 메시지를 직접 확인할 때 빠뜨리지 않아야 한다.

## 핵심 정리

- HTTP는 요청과 응답으로 데이터를 교환한다.
- 클라이언트와 서버의 역할을 분리하면 독립적인 변경이 쉬워진다.
- 무상태 요청은 필요한 문맥을 요청에 담아 서버 확장에 유리하다.
- 연결을 계속 점유하지 않는 성질은 자원 절약에 도움이 된다.
- 지속 연결은 반복적인 연결 비용을 줄인다.
- HTTP 메시지는 시작 줄, 헤더, 빈 줄, 본문으로 구성된다.
