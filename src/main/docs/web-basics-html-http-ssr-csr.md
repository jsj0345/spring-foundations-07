# 정적 리소스, HTML, HTTP API, SSR과 CSR 복습

> 서버가 무엇을 응답하고 화면을 어디에서 완성하는지에 따라 웹 전달 방식을 구분해서 정리했다.

## 1. 정적 리소스

서버에 미리 저장된 파일을 거의 그대로 전달한다.

```text
HTML
CSS
JavaScript
이미지
영상
```

```http
GET /assets/main.css
```

요청마다 업무 데이터를 조합하지 않아도 되므로 웹 서버나 CDN을 통해 효율적으로 제공하기 좋다.

파일이 바뀌지 않는 동안 캐시를 적극 활용할 수 있다.

## 2. 서버가 만든 HTML 페이지

서버가 요청 시점의 데이터를 이용해 최종 HTML을 생성한다.

```text
브라우저 요청
→ 서버가 데이터 조회
→ HTML 완성
→ 브라우저에 전달
→ 브라우저가 표시
```

사용자는 완성된 문서를 받기 때문에 첫 화면을 빠르게 볼 수 있고 검색 엔진이 내용을 읽기 쉬운 경우가 많다.

화면 이동마다 서버에서 새 HTML을 받아야 하면 상호작용이 많은 UI에서는 전체 페이지 전환이 반복될 수 있다.

## 3. HTTP API

서버가 HTML 대신 데이터를 응답한다.

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 1,
  "name": "userA"
}
```

JSON 같은 데이터는 여러 종류의 클라이언트가 공통으로 사용할 수 있다.

- 웹 브라우저 JavaScript
- 모바일 앱
- 다른 서버
- 데스크톱 프로그램

API는 화면 모양보다 데이터와 업무 기능을 제공한다.

## 4. SSR

Server-Side Rendering은 서버에서 화면에 필요한 HTML을 완성해 전달하는 방식이다.

```text
서버 → 완성된 HTML
브라우저 → HTML 표시
```

장점으로 볼 수 있는 부분:

- 초기 문서가 이미 채워져 있음
- 검색 엔진과 문서 공유에 유리할 수 있음
- 클라이언트 JavaScript 의존이 비교적 낮을 수 있음

한계:

- 화면 이동 시 서버 렌더링 요청이 반복될 수 있음
- 서버가 HTML 생성 부하를 담당
- 복잡한 상호작용에는 추가 JavaScript가 필요

## 5. CSR

Client-Side Rendering은 브라우저가 JavaScript를 실행하고 API 데이터를 받아 화면을 구성하는 방식이다.

```text
최초 HTML·JavaScript 수신
→ JavaScript 실행
→ API 데이터 요청
→ 브라우저가 화면 생성
```

장점:

- 화면 일부만 갱신하는 상호작용에 유리
- 웹과 API 서버의 역할을 분리하기 쉬움
- 최초 로딩 뒤 부드러운 화면 전환 가능

한계:

- JavaScript 파일이 크면 첫 화면이 늦어질 수 있음
- 클라이언트 상태와 오류 처리가 복잡해질 수 있음
- 검색 노출을 위해 추가 렌더링 전략이 필요할 수 있음

## 6. 둘 중 하나만 선택하는 문제는 아님

현대 웹 애플리케이션은 SSR과 CSR을 섞어 사용할 수 있다.

```text
초기 화면 → 서버에서 HTML 제공
이후 상호작용 → 브라우저가 API 호출 후 일부 갱신
```

페이지 성격에 따라 렌더링 위치를 선택하는 것이 중요하다.

- 검색과 초기 표시가 중요함
- 사용자 상호작용이 많음
- 네트워크와 기기 성능
- 서버 부하
- 캐시 전략
- 개발 복잡도

## 7. 구분 기준

| 방식 | 서버 응답 | 화면 완성 위치 |
|---|---|---|
| 정적 리소스 | 저장된 파일 | 파일 자체 또는 브라우저 |
| 동적 HTML | 완성된 HTML | 서버 |
| HTTP API | JSON 등 데이터 | 클라이언트가 사용 |
| SSR | 렌더링된 HTML | 주로 서버 |
| CSR | 데이터와 JavaScript | 주로 브라우저 |

## 핵심 정리

- 정적 리소스는 저장된 파일을 그대로 제공한다.
- 동적 HTML은 서버가 요청 시점에 화면을 만들어 전달한다.
- HTTP API는 화면 대신 데이터를 제공한다.
- SSR은 서버에서, CSR은 브라우저에서 화면을 주로 완성한다.
- 실제 서비스에서는 초기 렌더링과 이후 상호작용을 섞어 사용할 수 있다.
