# 인터넷 네트워크 기초 복습

> IP, TCP, UDP, PORT, DNS가 각각 어떤 문제를 해결하는지 계층적으로 정리했다.

## 1. 인터넷에서 데이터가 이동하는 방식

멀리 떨어진 두 컴퓨터는 하나의 케이블로 직접 연결되지 않는다. 데이터는 여러 네트워크 장비와 경로를 거쳐 목적지로 이동한다.

이때 목적지를 식별하고 패킷을 전달하기 위한 기본 규칙이 IP다.

## 2. IP의 역할

IP 패킷에는 출발지와 목적지 주소 같은 정보가 들어간다.

```text
출발지 IP
목적지 IP
전달할 데이터
기타 제어 정보
```

중간 노드들은 목적지 IP를 참고해 다음 경로로 패킷을 전달한다.

IP는 주소와 전달이라는 기본 기능을 제공하지만 다음을 완전히 보장하지 않는다.

- 대상 서버가 실제로 동작 중인지
- 패킷이 도착했는지
- 여러 패킷의 순서가 맞는지
- 중복이나 손실이 없는지

## 3. 프로토콜 계층

학습 단계에서는 다음처럼 나누어 이해했다.

```text
애플리케이션 계층 → HTTP
전송 계층         → TCP, UDP
인터넷 계층       → IP
네트워크 인터페이스 계층
```

상위 계층의 데이터가 아래 계층의 정보로 감싸져 전송되고 수신 측에서 역순으로 해석된다.

## 4. TCP

TCP는 IP 위에서 신뢰성 있는 데이터 전달을 돕는다.

대표적인 특성:

- 연결 수립
- 데이터 도착 여부 확인
- 전송 순서 보정
- 흐름과 혼잡 제어

연결을 시작할 때는 양쪽의 통신 가능 여부와 초기 정보를 맞추는 과정이 필요하다.

TCP가 안정성을 제공하는 대신 연결 관리와 확인 절차에 비용이 든다.

## 5. UDP

UDP는 연결 수립과 전달 보증 기능이 단순하다.

- 연결 과정 없음
- 순서 보장 없음
- 재전송 보장 없음
- 헤더가 비교적 단순함
- 애플리케이션이 필요한 기능을 직접 설계 가능

빠른 전달이나 애플리케이션 수준에서 별도 신뢰성 제어를 하는 경우에 사용할 수 있다.

UDP가 무조건 TCP보다 좋거나 나쁜 것이 아니라 필요한 보장 수준이 다르다.

## 6. PORT

하나의 컴퓨터는 동시에 여러 네트워크 프로그램을 실행한다.

```text
IP   → 어느 컴퓨터인가
PORT → 그 컴퓨터의 어느 애플리케이션인가
```

브라우저, 채팅, 게임이 같은 PC에서 통신하더라도 각 연결은 IP와 포트 조합으로 구분된다.

서버의 대표 포트와 클라이언트가 임시로 사용하는 포트가 함께 연결을 식별한다.

## 7. DNS

사람이 숫자 IP를 외우고 변경 사항을 직접 추적하기는 어렵다.

DNS는 도메인 이름을 IP 주소로 조회할 수 있게 한다.

```text
브라우저: example.com의 IP 요청
DNS: 연결할 IP 응답
브라우저: 받은 IP로 서버 접속
```

도메인이 같아도 상황에 따라 여러 IP가 반환될 수 있고, IP가 변경돼도 사용자는 같은 도메인을 사용할 수 있다.

DNS 조회 결과도 일정 시간 캐시될 수 있어 변경 직후 모든 사용자가 즉시 새 주소를 받는 것은 아닐 수 있다.

## 8. 전체 연결 흐름

```text
도메인 입력
→ DNS로 IP 조회
→ 목적지 IP와 PORT 결정
→ TCP 또는 UDP로 데이터 전달 준비
→ IP 패킷이 네트워크를 이동
→ 서버 애플리케이션이 요청 처리
```

## 핵심 정리

- IP는 컴퓨터 주소와 패킷 전달을 담당한다.
- IP만으로 도착, 순서, 신뢰성을 모두 보장하지 않는다.
- TCP는 연결과 신뢰성 기능을 제공하고 UDP는 단순성과 유연성이 크다.
- PORT는 한 컴퓨터 안의 애플리케이션을 구분한다.
- DNS는 사람이 사용하는 도메인을 네트워크 주소로 연결한다.
