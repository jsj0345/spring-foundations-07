# 웹 요청과 멀티스레드 복습

> WAS가 동시에 들어오는 요청을 처리할 때 왜 스레드 풀을 사용하는지와 애플리케이션 코드가 지켜야 할 점을 정리했다.

## 1. 요청은 누가 실행하는가

클라이언트의 HTTP 요청이 WAS에 도착하면 서버는 단순히 메시지만 전달하는 것이 아니다.

```text
네트워크 연결 확인
→ HTTP 메시지 해석
→ 요청 URL에 맞는 서블릿 선택
→ 애플리케이션 로직 실행
→ HTTP 응답 생성
```

이 과정에서 실제 Java 코드를 실행하는 흐름이 스레드다.

서블릿 객체가 있다고 해서 스스로 실행되는 것은 아니며, WAS가 배정한 스레드가 서블릿 메서드를 호출한다.

## 2. 스레드가 하나뿐일 때

요청 A를 처리하는 중 데이터베이스나 외부 API에서 오래 기다린다고 생각해 보자.

```text
스레드 1 → 요청 A 처리 중 대기
요청 B   → 실행할 스레드가 없어 대기
```

하나의 느린 요청이 뒤에 온 요청까지 막아 전체 응답 시간이 길어질 수 있다.

## 3. 요청마다 새 스레드를 만들면

각 요청에 별도 스레드를 만들면 여러 요청을 동시에 처리할 수 있다.

하지만 요청이 들어올 때마다 생성하는 구조에는 한계가 있다.

- 스레드 생성과 종료 비용
- 스레드마다 필요한 스택 메모리
- 너무 많은 스레드로 인한 컨텍스트 스위칭
- 요청 폭증 시 메모리와 CPU 고갈
- 스레드 수를 통제하기 어려움

동시 처리 능력은 늘지만 서버 자원을 무한히 사용할 수는 없다.

## 4. 스레드 풀

WAS는 보통 일정 수의 작업 스레드를 관리하는 풀을 사용한다.

```text
요청 도착
→ 풀에서 사용 가능한 스레드 획득
→ 요청 처리
→ 처리가 끝나면 스레드를 풀에 반환
```

사용 가능한 스레드가 없으면 새 요청은 대기열에 들어가거나 설정된 정책에 따라 거절될 수 있다.

스레드를 재사용하므로 매 요청마다 생성하는 비용을 줄이고 최대 동시 실행 수를 제한할 수 있다.

## 5. 최대 스레드 수의 의미

최대값이 너무 작으면 CPU와 메모리에 여유가 있어도 요청이 큐에서 오래 기다린다.

반대로 너무 크게 잡으면 다음 문제가 생길 수 있다.

- 메모리 사용량 증가
- 컨텍스트 스위칭 증가
- 데이터베이스 커넥션 부족
- 외부 시스템으로 과도한 요청 전달
- 장애 시 요청이 한꺼번에 쌓이는 현상

적정 값은 CPU 개수만으로 정할 수 없다. 요청 로직의 계산량, I/O 대기, DB 커넥션 수, 목표 응답 시간, 실제 트래픽을 함께 측정해야 한다.

## 6. 장애 상황에서 보는 지표

스레드 풀이 모두 사용 중이면 요청이 늦어질 수 있으므로 다음을 함께 관찰하는 편이 좋다.

- 활성 스레드 수
- 최대 스레드 수
- 요청 대기 큐 길이
- 평균 및 상위 응답 시간
- DB 커넥션 풀 사용량
- CPU와 메모리
- 시간 초과 및 거절 횟수

단순히 최대 스레드만 늘리면 병목이 DB나 외부 API로 이동할 수 있다.

## 7. WAS가 멀티스레드를 지원해도 코드가 자동으로 안전해지는 것은 아님

개발자는 요청마다 스레드를 직접 생성하지 않아도 된다. 그러나 여러 요청이 같은 객체를 동시에 사용할 수 있다는 사실은 고려해야 한다.

서블릿과 스프링 싱글톤 빈의 공유 필드에 사용자별 값을 저장하면 요청 데이터가 섞일 수 있다.

```java
// 공유 빈에서 피해야 할 형태
private String currentUser;
```

요청별 데이터는 지역 변수, 메서드 파라미터, 요청 스코프 등 적절한 위치에 둬야 한다.

## 8. 내가 이해한 역할 분담

```text
WAS
→ 스레드 생성·재사용·배정·종료 관리

애플리케이션 개발자
→ 공유 상태를 안전하게 설계
→ 오래 걸리는 작업과 병목 관리
→ 풀 크기와 타임아웃을 운영 환경에 맞게 조정
```

## 핵심 정리

- 서버의 Java 로직은 WAS가 배정한 스레드에서 실행된다.
- 단일 스레드는 하나의 느린 요청 때문에 전체가 막힐 수 있다.
- 요청마다 새 스레드를 만들면 자원 고갈 위험이 있다.
- 스레드 풀은 재사용과 최대 동시 처리 수 제한을 제공한다.
- 최대 스레드 수는 애플리케이션과 외부 자원을 측정해 정해야 한다.
- WAS가 스레드를 관리해도 공유 객체의 스레드 안전성은 개발자가 지켜야 한다.
